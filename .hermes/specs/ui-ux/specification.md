# Specification: UI/UX 요구사항 (사용자 경험 중심)

## Goal
KIYO 앱의 모든 사용자 액션에 대해 명시적인 반응(로딩·실패·비활성화)과 각 상태에 대한 명시적 안내(암호화된 파일 아이콘, 볼트 상태, 자동 잠금 등)를 제공하여, 사용자가 현재 앱이 어떤 상태인지 항상 인지할 수 있도록 한다. 성공 시에는 페이지 이동이나 상태 변경 자체가 안내 역할을 하므로 별도 알림은 불필요하다.

## Context / Assumptions

### 현재 상태 (Current State)
KIYO는 React 19 + Zustand + Capacitor 기반 Android 앱으로, 다음과 같은 주요 사용자 플로우가 존재한다.

| 항목 | 현황 | 소스 |
|------|------|------|
| 볼트 생명주기 | 생성·잠금 해제·잠금·닫기, 암호화 키는 메모리만 | `vault-session` 스펙, `vaultPersistence.ts` |
| 계정 CRUD | 생성·수정·삭제·전체 삭제, 자동 저장(requestSave) | `account-crud` 스펙, `accountStore.ts` |
| 템플릿 CRUD | 생성·수정·삭제, 계정과 동일한 자동 저장 패턴 | `template-crud` 스펙 |
| 자동 잠금 | `none` / `1m` / `10m` / `30m`, 활동 감지 시 리셋 | `useAutoLock.ts` |
| 암호화 | PIN → PBKDF2(100k) → AES-GCM-256, 볼트 전체 단일 암호화 | `fileStorage.ts`, `encryption.ts` |
| 파일 저장 | Dexie IndexedDB + 외부 파일 시스템(JSON 볼트) | `fileStorage.ts` |
| 네트워크 | 전송 없음 (오프라인 전용) | AGENTS.md |

### 전제 조건 (Assumptions)
1. 타겟 플랫폼은 Android (API 26+) WebView 기반 Capacitor 앱이다.
2. 모든 데이터는 기기 로컬에만 저장되며, 네트워크 호출은 전혀 발생하지 않는다.
3. 암호화 키(cryptoKey)는 메모리(SecuritySession)에만 존재하며, 디스크에 persist되지 않는다.
4. 볼트 잠금 해제 시 PIN 기반 PBKDF2 키 유도가 필요하므로, 사용자는 지연(로딩)을 인지할 수 있어야 한다.
5. 자동 잠금 설정은 `none` / `1m` / `10m` / `30m` 중 하나이며, 활동 감지 시 타이머가 리셋된다.
6. 볼트 파일은 암호화된 상태(encrypted) 또는 평문 상태일 수 있으며, 사용자는 두 상태를 시각적으로 구별할 수 있어야 한다.

## Functional Requirements

### FR-1: 사용자 액션에 대한 명시적 로딩 반응

#### FR-1.1: 볼트 잠금 해제(Unlock) 중 로딩
**Given** 사용자가 PIN을 입력하고 잠금 해제를 요청한다  
**When** `unlockVault(fileName, pin)`이 실행 중이다  
**Then** 앱은 "잠금 해제 중…" 상태를 명시적으로 표시해야 하며, PIN 입력 필드와 잠금 해제 버튼은 비활성화되어 중복 요청을 방지해야 한다. 동일한 작업이 다른 경로(뒤로 가기 등)로 실행될 수 없도록 해야 한다.

#### FR-1.2: 볼트 생성(Create) 중 로딩
**Given** 사용자가 파일명과 PIN을 입력하고 볼트 생성을 요청한다  
**When** `createDataFile(fileName, pin)`이 실행 중이다  
**Then** 앱은 "볼트 생성 중…" 상태를 명시적으로 표시해야 하며, 생성 버튼은 비활성화되어야 한다. 동일한 작업이 다른 경로로 실행될 수 없도록 해야 한다.

#### FR-1.3: 볼트 잠금(Lock) 중 로딩
**Given** 볼트가 잠금 해제된 상태에서 사용자가 잠금을 요청한다  
**When** `lockVault()`가 실행 중이다  
**Then** 앱은 "잠금 중…" 상태를 명시적으로 표시해야 하며, 볼트 관련 조회/수정 액션은 비활성화되어야 한다.

#### FR-1.4: 계정·템플릿 CRUD 중 로딩
**Given** 사용자가 계정 생성·수정·삭제를 요청한다  
**When** Store 연산(`addAccount`/`updateAccount`/`deleteAccount`)과 자동 저장(requestSave)이 실행 중이다  
**Then** 앱은 "저장 중…" 상태를 명시적으로 표시해야 하며, 해당 폼의 입력 필드와 제출 버튼은 비활성화되어야 한다. 동일한 작업이 다른 경로로 실행될 수 없도록 해야 한다.

#### FR-1.5: 볼트 가져오기/내보내기 중 로딩
**Given** 사용자가 볼트 파일을 가져오거나 내보내기를 요청한다  
**When** 파일 입출력 연산이 실행 중이다  
**Then** 앱은 "처리 중…" 상태를 명시적으로 표시해야 하며, 파일 선택/내보내기 버튼은 비활성화되어야 한다.

### FR-2: 사용자 액션에 대한 명시적 실패 반응

실패 메시지는 다음 규칙을 따라야 한다.
- 사용자에게 원인을 이해할 수 있는 한국어 메시지를 제공해야 한다.
- 내부 예외 메시지, Stack Trace, 암호화 키, PIN, 복호화 단계 등 민감 정보를 직접 노출해서는 안 된다.
- 재시도 가능한 오류와 불가능한 오류를 구분하여, 재시도 가능 시 "다시 시도" 액션을 제공해야 한다.

#### FR-2.1: 볼트 잠금 해제 실패 (잘못된 PIN)
**Given** 잘못된 PIN이 입력되어 복호화가 실패한다  
**When** `unlockVault()`가 PIN_MISMATCH 오류를 반환한다  
**Then** 앱은 "PIN이 일치하지 않습니다"와 같은 명시적 실패 메시지를 표시해야 하며, cryptoKey는 메모리에 남기지 않아야 한다. 오라클 방지를 위해 구체적 실패 원인(예: 복호화 실패 단계)은 외부에 노출하지 않는다. 재시도를 위해 PIN 입력 필드는 유지하고, 포커스를 PIN 입력으로 이동해야 한다.

#### FR-2.2: 볼트 생성 실패
**Given** 파일명 중복, 저장 공간 부족 등의 이유로 볼트 생성이 실패한다  
**When** `createDataFile()`가 오류를 반환한다  
**Then** 앱은 생성 실패 원인을 사용자가 이해할 수 있는 한국어 메시지로 명시적으로 표시해야 하며, 입력 필드는 유지되어 재시도 가능해야 한다.

#### FR-2.3: 볼트 잠금/닫기 실패
**Given** `lockVault()` 또는 `closeDataFile()` 실행 중 오류가 발생한다  
**Then** 앱은 실패를 명시적으로 표시해야 하며, 사용자가 실패를 인지할 수 있도록 에러 메시지를 보여준다.

#### FR-2.4: 계정·템플릿 CRUD 실패
**Given** 자동 저장(requestSave)이 실패한다  
**When** Store 연산은 성공했으나 IndexedDB/파일 저장 실패  
**Then** 앱은 저장 실패를 명시적으로 표시해야 하며, 사용자가 변경 사항을 잃지 않도록 재시도 또는 "나중에 저장" 옵션을 제공해야 한다.

#### FR-2.5: 네트워크/오프라인 상태 (필수)
**Given** 앱이 오프라인 상태이다 (항상 오프라인 전용)  
**When** 사용자가 어떤 액션을 수행한다  
**Then** 앱은 네트워크 의존성 없이 모든 작업을 로컬로 처리하며, 오프라인임을 별도로 안내하지 않아도 된다 (모든 기능이 오프라인으로 동작함이 기본 가정).

### FR-3: 사용자 액션에 대한 명시적 비활성화 반응

#### FR-3.1: 연속 입력 방지 (중복 액션 비활성화)
**Given** 볼트 잠금 해제 중, 생성 중, 저장 중 등 동일한 작업이 이미 실행 중이다  
**When** 사용자가 동일한 액션 버튼을 다시 클릭하거나 다른 경로(뒤로 가기 등)로 동일 작업을 시도한다  
**Then** 해당 액션 버튼은 비활성화되어 중복 실행을 방지해야 한다.

#### FR-3.2: 파괴적 액션 확인 (계정 삭제 등)
**Given** 사용자가 계정 삭제, 볼트 닫기 등 데이터를 소실시킬 수 있는 파괴적 액션을 요청한다  
**When** 해당 액션을 실행하려 한다  
**Then** 앱은 확인 모달("정말 삭제하시겠습니까?", "저장 후 닫으시겠습니까?" 등)을 표시해야 하며, 사용자 확인 전까지 액션을 진행해서는 안 된다.

### FR-4: 각 상태에 대한 명시적 안내

#### FR-4.1: 볼트 잠금/잠금 해제 상태 안내
**Given** 볼트 상태가 변경된다  
**Then** 앱은 현재 볼트 상태(잠김 / 잠금 해제됨 / 생성 중 / 닫힘)를 화면 상단이나 볼트 목록에 명시적으로 표시해야 한다. 아이콘(잠금 아이콘 등)과 컬러 배지, 텍스트 라벨을 조합하여 사용자가 한눈에 인지할 수 있어야 한다.

#### FR-4.2: 암호화된 파일 vs 평문 파일 상태 안내
**Given** 볼트 파일이 암호화된 상태이거나 평문 상태이다  
**When** 사용자가 볼트 파일을 선택하거나 목록을 본다  
**Then** 앱은 암호화된 파일에 대해 "암호화됨" 아이콘(예: 자물쇠 아이콘)과 라벨을, 평문 파일에 대해 "평문" 아이콘과 라벨을 명시적으로 표시해야 한다. 사용자가 파일 보안 상태를 혼동하지 않도록 시각적 구별이 분명해야 한다.

#### FR-4.3: 자동 잠금 상태 안내
**Given** 자동 잠금 설정이 `1m` / `10m` / `30m` 중 하나로 설정되어 있다  
**When** 자동 잠금 타이머가 실행 중이다  
**Then** 앱은 남은 잠금 시간(예: "30초 후 자동 잠금")을 명시적으로 표시해야 하며, 사용자 활동 시 타이머가 리셋(갱신)됨을 시각적으로 안내해야 한다. 잠금 처리 중에는 남은 시간 표시 대신 처리 상태를 표시해야 한다. `none` 설정 시에는 자동 잠금 비활성화 상태를 표시해야 한다.

#### FR-4.4: 세션 상태 안내 (암호화 키 메모리 존재 여부)
**Given** 세션이 구성되거나 초기화된다  
**When** `cryptoKey`가 메모리에 존재하는지 여부가 변경된다  
**Then** 앱은 "세션 활성" / "세션 만료"를 명시적으로 표시해야 한다.

#### FR-4.5: 저장 상태 안내 (자동 저장)
**Given** 계정·템플릿 데이터가 변경되어 자동 저장이 트리거된다  
**When** `requestSave()`가 실행 중이거나 완료/실패한다  
**Then** 앱은 "저장 중…" / "저장 완료" / "저장 실패"를 일시적인 토스트 형태로 명시적으로 표시해야 하며, 사용자가 데이터 persistence 상태를 항상 인지할 수 있어야 한다. "저장 완료" 토스트는 일정 시간 후 자동으로 사라져야 한다.

#### FR-4.6: 빈 상태(Empty State) 안내
**Given** 볼트에 계정이 없거나, 검색 결과가 없거나, 템플릿이 없다  
**When** 사용자가 해당 화면을 조회한다  
**Then** 앱은 "계정이 없습니다" / "검색 결과가 없습니다"와 같은 명시적 빈 상태 안내와 함께, 해당 액션을 시작할 수 있는 버튼(예: "계정 추가")을 함께 제공해야 한다.

#### FR-4.7: 입력 유효성 안내
**Given** 사용자가 잘못된 입력값을 입력한다 (예: PIN 길이 부족, 잘못된 파일명 등)  
**When** 입력값에 대한 유효성 검증이 실패한다  
**Then** 앱은 입력 필드 근처에 즉각적인 안내 메시지를 표시해야 하며, 제출 버튼은 비활성화되거나 클릭 시 유효성 오류를 안내해야 한다.

#### FR-4.8: 오류 복구 안내
**Given** 오류가 발생하여 사용자가 조치를 취해야 한다  
**When** 오류 메시지가 표시된다  
**Then** 앱은 오류 메시지와 함께 복구를 위한 다음 액션(예: "PIN 재입력", "다시 시도", "설정 확인")을 명시적으로 안내해야 한다. 오류 발생 시 사용자가 수정해야 할 입력으로 포커스를 이동해야 한다.

## Non-Functional Requirements

| 카테고리 | 요구사항 | 측정/검증 방법 |
|----------|----------|---------------|
| **사용자 경험** | 모든 사용자 액션에 로딩·실패·비활성화 반응이 명시적으로 표시되어야 한다 | UI 스크린샷 기반 수동 검증, E2E 테스트 |
| **사용자 경험** | 자동 잠금, 저장 상태가 시각적으로 구별되어야 한다 | UI 스크린샷 기반 수동 검증 |
| **접근성** | 로딩/실패 상태는 색상뿐만 아니라 아이콘·텍스트·ARIA 라벨로도 전달되어야 한다 | 스크린 리더 테스트, axe-core 접근성 검사 |
| **보안** | 실패 메시지에서 암호화 키, PIN, 복호화 단계 등 민감 정보는 노출되지 않아야 한다 | 오류 메시지 코드 리뷰 |
| **보안** | 볼트 잠김 상태에서는 민감 데이터(계정 목록 등)가 화면에 표시되지 않아야 한다 | UI 코드 리뷰 |
| **오프라인 우선** | 모든 UI 반응은 네트워크 없이 로컬에서 즉시 처리되어야 한다 | 네트워크 차단 테스트 |
| **성능** | 로딩 상태 진입은 사용자 액션 후 100ms 이내, PBKDF2 키 유도(100k)는 1초 이내 완료되어야 한다 | 성능 측정 |
| **TypeScript strict** | ESM only, `@/` → `src/`, strict 모드 준수 | `npm run typecheck` |
| **테스트** | `npm run typecheck`, `npm run lint`, `npm run test` 모두 통과 | CI 검증 |

## Out of Scope (명시적 제외)
다음 항목은 본 UI/UX 스펙의 범위에 포함하지 않는다. 실제 구현이 존재하더라도 '나중에 구현 예정'으로 명시한다.

1. **개별 화면의 버튼 라벨 및 좌표**: 본 스펙은 사용자 경험과 상태 전이에 집중하며, 개별 버튼 텍스트나 레이아웃詳細は 디자인 시스템/컴포넌트 스펙으로 별도 정의.
2. **애니메이션 세부사항**: 페이드인/아웃, 슬라이드 등 모션 디테일은 별도 디자인 스펙.
3. **다크/라이트 테마 구체적 컬러 값**: 테마 구조는 `settings` 스펙 참조, 구체적 토큰 값은 디자인 시스템.
4. **Android 네이티브 UI (Kotlin/View)**: 본 스펙은 React/WebView 측 UI/UX에 집중. 네이티브 오버레이·생체인증 다이얼로그는 `android-security` 스펙 참조.
5. **온보딩/튜토리얼 화면**: 최초 실행 시 안내 흐름은 별도 스펙.
6. **클라우드 동기화 UI**: 모든 데이터는 기기 로컬에만 저장되므로 동기화 관련 UI는 제외.
7. **볼트 잠금/잠금 해제 상태 안내 (FR-4.1)**: 현재 구현되지 않음. 추후 볼트 상태(잠김 / 잠금 해제됨)를 화면 상단이나 볼트 목록에 아이콘·배지·텍스트로 표시하는 UI 컴포넌트를 별도 구현할 예정.
8. **암호화된 파일 vs 평문 파일 상태 안내 (FR-4.2)**: 현재 구현되지 않음. 추후 암호화된 파일에 자물쇠 아이콘과 "암호화됨" 라벨, 평문 파일에 "평문" 아이콘과 라벨을 표시하는 UI 컴포넌트를 별도 구현할 예정.
9. **자동 저장 상태 토스트 (FR-4.5)**: 현재 구현되지 않음. 추후 "저장 중…" / "저장 완료" / "저장 실패"를 일시적인 토스트로 표시하는 컴포넌트를 별도 구현할 예정.
10. **빈 상태(Empty State) 안내 (FR-4.6)**: 현재 구현되지 않음. 추후 "계정이 없습니다" 등 빈 상태 안내와 시작 버튼을 별도 구현할 예정.

## Acceptance Criteria
이 spec이 완료됐다고 판단할 조건:

1. **AC-1**: 볼트 잠금 해제·생성·잠금·닫기, 계정·템플릿 CRUD 모든 사용자 액션에 로딩 상태가 명시적으로 표시된다.
2. **AC-2**: 모든 사용자 액션에 실패 반응이 명시적으로 표시되며, 실패 메시지는 한국어로 사용자가 이해할 수 있어야 한다. 내부 예외나 Stack Trace는 노출되지 않아야 한다.
3. **AC-3**: 자동 저장 상태는 일시적인 토스트로 "저장 중…" / "저장 완료" / "저장 실패"가 명시적으로 표시된다. "저장 완료"는 일정 시간 후 자동으로 사라져야 한다.
4. **AC-4**: 자동 잠금 남은 시간이 명시적으로 표시되며, 사용자 활동 시 타이머가 갱신되어야 한다.
5. **AC-5**: 오류 메시지에서 암호화 키, PIN, 복호화 단계 등 민감 정보가 노출되지 않는다.
6. **AC-6**: 입력 유효성 실패 시 입력 필드 근처에 즉각적인 안내 메시지가 표시되며, 오류 발생 시 사용자가 수정해야 할 입력으로 포커스가 이동해야 한다.
7. **AC-7**: 계정 삭제 등 파괴적 액션 실행 전 확인 모달이 표시되어야 한다.
8. **AC-8**: `npm run typecheck`, `npm run lint`, `npm run test`가 모두 통과한다.
9. **AC-9**: 헌법 §8 위반 체크리스트 전 항목 통과.

> **참고**: FR-4.1(볼트 잠금/잠금 해제 상태 안내)과 FR-4.2(암호화된 파일 vs 평문 파일 상태 안내)는 Out of Scope에 따라 미구현 상태이며, 추후 구현 시 별도 검증 대상으로 삼는다.
